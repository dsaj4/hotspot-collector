# Browser Use CDP Agent Guide

Purpose: attach Browser Use to the real Chrome/Edge session opened by Hotspot Collector and produce a `BrowserObservation` without broad automation.

## Sources

- Browser Use CLI supports real Chrome/profile sessions, `--cdp-url`, `state`, screenshots, JavaScript `eval`, and persistent sessions.
- Browser Use browser settings include `cdp_url` for connecting to an existing browser instance.

## Operator Prompt

Use this prompt when delegating the collection step to an agent:

```text
You are collecting visible social-page items for Hotspot Collector.

Connect to the existing browser through CDP. Inspect the current visible page only.
Return a BrowserObservation JSON object with sourceId, platform, streamType, pageUrl, status, capturedAt, and items.
Set collectionMethod to "browser-use-agent" when you perform interactive Browser Use control before saving the observation.

Allowed:
- browser-use state
- browser-use eval with read-only DOM JavaScript
- browser-use screenshot when evidence is requested

Not allowed:
- clicking, typing, form submission, login, CAPTCHA handling, cookie reads, profile sync, cloud browser provisioning
- long scrolling or broad collection without explicit user approval
- collecting hidden/private/account-only data beyond visible selected items

Stop and return status "unavailable" if the page shows a login wall, CAPTCHA, anti-bot prompt, or paywall.
```

## Command Sequence

```text
npm.cmd run browser:cdp -- --platform=bilibili --port=9223 --url=https://www.bilibili.com/v/popular/all/
$env:PYTHONIOENCODING="utf-8"; browser-use doctor
$env:PYTHONIOENCODING="utf-8"; browser-use --session hotspot-social --cdp-url http://127.0.0.1:9223 open https://www.bilibili.com/v/popular/all/
$env:PYTHONIOENCODING="utf-8"; browser-use --session hotspot-social --cdp-url http://127.0.0.1:9223 state
powershell -ExecutionPolicy Bypass -File skills/social-browser-collection/skill/scripts/browser-use-cdp-visible-collect.ps1 -Platform bilibili -Port 9223 -Url "https://www.bilibili.com/v/popular/all/" -StreamType hotspot -Limit 8 -Output data/demo/browser-use-bilibili-popular-observation.json
npm.cmd run social:ingest -- --input=data/demo/browser-use-bilibili-popular-observation.json
```

On Windows terminals that default to GBK, set `PYTHONIOENCODING=utf-8` before Browser Use commands. Without it, `browser-use doctor` can fail while printing Unicode status icons.

On Windows, Browser Use maps each session name to a fixed localhost TCP port. Some mapped ports can fall inside Windows excluded port ranges and fail with `WinError 10013` / `Failed to start daemon`. The collection script checks the mapped port before starting Browser Use and automatically suffixes the session name when the original port cannot be bound.

The deterministic Browser Use script uses the shared extraction script generated by `browser:extraction-script`. Direct CDP uses the same script through `browser:collect-social`, so extraction fixes should be made in `src/collection/social/browser-extraction.ts`.

The intended collection order is:

1. `browser-use-script`: Browser Use + CDP + deterministic extraction script.
2. `browser-use-agent`: Browser Use + CDP + interactive agent loop for visible clicks, scrolling, waiting, or page inspection.
3. `direct-cdp`: project CDP fallback through `browser:collect-social`.

For a strict Browser Use smoke test, pass `-BrowserUseOnly`; this disables direct-CDP fallback and makes Browser Use failures visible.

Direct CDP command:

```text
npm.cmd run browser:collect-social -- --platform=bilibili --stream=hotspot --source=bilibili-browser-use-cdp --port=9223 --url=https://www.bilibili.com/v/popular/all/ --limit=8
```

## Codex Operator Fallback

When Codex exposes `node_repl`, an operator can use it as a browser-control fallback without adding a repo runtime dependency. The path is:

1. Keep the project browser open with `npm.cmd run browser:cdp`.
2. From `node_repl`, fetch `http://127.0.0.1:<port>/json`, choose the visible `page` target for the public URL, and connect to its `webSocketDebuggerUrl`.
3. Send only read-only CDP commands such as `Runtime.evaluate` with the same visible DOM extraction expression used by the project collector.
4. Save the returned object as a `BrowserObservation`, then run `social:ingest`.

Do not use `node_repl` to read cookies, local storage tokens, CAPTCHA state, private account data, or non-visible page internals.

## Acceptance

- Output is valid JSON accepted by `social:ingest`.
- Page interaction is read-only.
- Any login wall or CAPTCHA is represented as `status: "unavailable"`, not bypassed.
